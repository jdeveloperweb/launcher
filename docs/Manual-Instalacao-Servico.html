Manual de Instalação como Serviço — systemd + JDK portátil

Este manual instala o Worker de Integração POUPEX ↔ Cloud Prognum como um serviço do sistema (systemd) em Linux, usando um JDK portátil que acompanha o pacote — o worker roda independente da versão de Java instalada no servidor. Sem Docker.

1. Visão geral

O worker roda dentro do perímetro do cliente (on-premise), puxa eventos da Cloud Prognum por long polling autenticado com HMAC-SHA256 e os entrega ao destino local (wcertdox por HTTP, ou o banco do cliente por JDBC). Todo o tráfego externo é outbound — nada entra na rede do cliente vindo da Cloud.

Zero inbound O worker não abre nenhuma porta de rede. A observabilidade vive apenas em 127.0.0.1:9090 (loopback) — nenhuma porta é publicada e nenhuma regra de entrada no firewall é necessária.
Por que JDK portátil? O pacote inclui um JDK próprio (java21.tar.gz), extraído para dentro do diretório de instalação. O serviço aponta para esse Java — então a versão de Java do servidor (ou a ausência dela) não importa e não há conflito com outras aplicações.

3. Pré-requisitos no servidor

  • Linux x86_64 com systemd (Ubuntu, RHEL, Debian, Oracle Linux…).
  • Acesso root (sudo) para instalar o serviço.
  • NTP sincronizado — timedatectl status deve mostrar System clock synchronized: yes. A assinatura HMAC usa janela de timestamp: relógio errado = 401 em tudo.
  • Saída HTTPS liberada (porta 443) para o domínio da Cloud Prognum. Nenhuma porta de entrada é necessária.
  • wcertdox em execução na mesma máquina (modo http), acessível em localhost:<porta>.
  • Utilitários comuns: tar, wget (presentes na maioria das distros). jq é opcional, só para ler o /status formatado.
Não precisa de Java instalado O JDK vem no pacote. Também não precisa de Docker — esta é a instalação bare-metal.

4. Conteúdo do pacote

O pacote entregue é um tar.gz com tudo o que a instalação precisa:

worker-integration-service-1.0.0/
├── worker-integration.jar           # a aplicação
├── java21.tar.gz                     # JDK portátil (Java 21)
├── install-service.sh               # instalador (root): cria o serviço systemd
├── uninstall-service.sh             # remove o serviço (preserva dados por padrão)
├── worker.env.example               # template de configuração
├── hmac.json.example                # template do segredo HMAC
└── Manual-Instalacao-Servico.html   # este manual

Além do pacote, a Prognum fornece fora de banda (canal seguro): o segredo HMAC (hmac.json real) e a URL da Cloud do ambiente (dev/hml/prod). A x-api-key do wcertdox é do próprio ambiente do cliente.

5. Instalação passo a passo

  1. Copiar e extrair o pacote no servidor 
    tar -xzf worker-integration-service-1.0.0.tar.gz
cd worker-integration-service-1.0.0
  2. Preencher a configuração e o segredo

    Crie o worker.env a partir do exemplo e ajuste os valores CHANGE-ME (URL da Cloud, api-key do wcertdox, prefixo HMAC do ambiente). Crie também o hmac.json com o segredo fornecido:

    cp worker.env.example worker.env
nano worker.env            # ajuste PROGNUM_CLOUD_BASE_URL, WCERTDOX_*, CLOUD_HMAC_PATH_PREFIX

cp hmac.json.example hmac.json
nano hmac.json             # cole key_id e secret_b64 fornecidos pela Prognum
    Prefixo HMAC por ambiente CLOUD_HMAC_PATH_PREFIX = vazio em dev; /integration/v1 em hml/prod. Errar isso é a causa nº 1 de 401.

    Se preferir, pule este passo: o instalador copia os templates para /etc/worker-integration/ e pausa pedindo que você os edite antes de subir.

  3. Rodar o instalador como root

    O instalador pergunta como o serviço deve rodar — usuário dedicado (recomendado) ou root:

    sudo bash install-service.sh

    Ou escolha direto pela flag:

    sudo bash install-service.sh --user dedicated   # cria o usuário 'worker-integration'
sudo bash install-service.sh --user root        # roda como root

    O instalador então:

    • valida que o JAR e o java21.tar.gz estão presentes;
    • cria /opt/prognum/worker-integration, /var/lib/worker-integration (ledger) e /etc/worker-integration/secrets;
    • extrai o JDK portátil e confirma a versão do Java;
    • instala o worker.env (chmod 600) e o hmac.json (chmod 0400);
    • valida a config (recusa CHANGE-ME e segredo ausente) e avisa se o NTP estiver fora;
    • escreve a unit systemd, faz daemon-reload, enable e start;
    • confere /healthz e systemctl is-active ao final.
  4. Conferir que subiu

    Ao final, o instalador imprime o resumo e os comandos úteis. Confirme:

    systemctl status worker-integration
journalctl -u worker-integration -f

5.1 A unit systemd gerada

Para referência, a unit criada tem esta forma (usuário dedicado):

[Unit]
Description=Worker de Integração POUPEX <-> Cloud Prognum
After=network-online.target
Wants=network-online.target

[Service]
Type=simple
User=worker-integration
Group=worker-integration
WorkingDirectory=/opt/prognum/worker-integration
EnvironmentFile=/etc/worker-integration/worker.env
Environment=TZ=America/Sao_Paulo
ExecStart=/opt/prognum/worker-integration/jdk/bin/java \
          -XX:+UseParallelGC -Xms192m -Xmx384m \
          -jar /opt/prognum/worker-integration/worker-integration.jar
Restart=on-failure
RestartSec=15
NoNewPrivileges=true
ProtectSystem=strict
ProtectHome=true
PrivateTmp=true
ReadWritePaths=/var/lib/worker-integration /opt/prognum/worker-integration/logs
StandardOutput=journal
StandardError=journal

[Install]
WantedBy=multi-user.target
Modo root Se você escolher --user root, a unit é a mesma porém sem as linhas User=/Group=. O serviço roda como root.

Após editar o worker.env Se o serviço já estiver instalado, aplique as mudanças com sudo systemctl restart worker-integration (a unit lê o arquivo no start).

7. Operação (systemctl)

# Status do serviço
systemctl status worker-integration

# Logs em tempo real
journalctl -u worker-integration -f

# Últimas 100 linhas
journalctl -u worker-integration -n 100 --no-pager

# Parar / iniciar / reiniciar
sudo systemctl stop worker-integration
sudo systemctl start worker-integration
sudo systemctl restart worker-integration

# Habilitar/desabilitar start no boot
sudo systemctl enable worker-integration
sudo systemctl disable worker-integration
Reiniciar é seguro a qualquer momento A Cloud só descarta um evento após o ack do worker. Eventos não confirmados são reentregues quando o serviço volta — nada se perde.

7.1 Atualizar a versão

  1. Envie o novo pacote e extraia.
  2. Rode sudo bash install-service.sh novamente — ele substitui o JAR e o JDK, preserva worker.env, o segredo e o ledger já existentes, e reinicia o serviço.

8. Rotação do segredo HMAC (sem reiniciar)

  1. A Prognum cadastra a nova key_id na Cloud (passa a aceitar as duas).
  2. No servidor, sobrescreva o segredo mantendo as permissões: 
    sudo install -m 400 novo-hmac.json /etc/worker-integration/secrets/hmac.json
# se o serviço roda como usuário dedicado, ajuste o dono:
sudo chown worker-integration:worker-integration /etc/worker-integration/secrets/hmac.json
  3. O worker detecta a mudança e recarrega em até 1 minuto — sem reiniciar. Confirme: 
    curl -s http://127.0.0.1:9090/status | jq .active_key_id
  4. A Prognum revoga a key_id antiga.

9. Verificação e saúde

A observabilidade fica em 127.0.0.1:9090 (somente local):

# Vivo?
curl -s http://127.0.0.1:9090/healthz          # {"status":"ok"}

# Pronto? (modo + dependências)
curl -s http://127.0.0.1:9090/readyz | jq

# Estado e contadores
curl -s http://127.0.0.1:9090/status | jq
EndpointO que retorna
/healthzVivacidade: {"status":"ok"}.
/readyzProntidão: cloud_outbound, database_reachable (ledger no modo http), hmac_secret_loaded. 503 se alguma falhar.
/statusdelivery_mode, active_key_id e contadores (events_received, events_delivered, acks_sent, auth_rejections…).
/metricsFormato Prometheus.
Fluxo saudável events_received, events_delivered e acks_sent sobem juntos; auth_rejections e delivery_failures ficam em 0. Nos logs, Sem evento na janela se repetindo é o long polling normal.

10. Troubleshooting

SintomaCausa provávelAção
Serviço não inicia (systemctl status = failed) Variável obrigatória ausente/inválida no worker.env; segredo ausente journalctl -u worker-integration -n 50 — a mensagem do boot aponta a variável exata.
401 nos logs (Falha AUTH) Relógio fora de NTP; key_id/segredo errado; CLOUD_HMAC_PATH_PREFIX errado para o ambiente Conferir timedatectl; conferir o hmac.json; dev = vazio, hml/prod = /integration/v1.
/readyz = 503 Segredo não carregou ou ledger inacessível Conferir permissões do hmac.json (0400) e de /var/lib/worker-integration (gravável pelo usuário do serviço).
delivery_failures subindo wcertdox respondendo erro/500, payload fora do formato, porta errada Conferir WCERTDOX_URL/porta e os logs do wcertdox.
Evento "some" após N tentativas Poison: descarte por design após MAX_DELIVERY_ATTEMPTS Localizar o log ERROR ... descartado ... poison com o event_id; corrigir a causa e solicitar reinjeção.
java: cannot execute / erro de Java no start JDK portátil não compatível com a arquitetura, ou tarball corrompido Confirmar que o java21.tar.gz é Linux x64; testar /opt/prognum/worker-integration/jdk/bin/java -version.

11. Desinstalação

# Remove o serviço, PRESERVANDO dados (ledger, worker.env e segredo)
sudo bash uninstall-service.sh

# Remove o serviço E apaga todos os dados
sudo bash uninstall-service.sh --purge

O modo padrão para e remove o serviço e os binários (/opt/prognum/...), mas mantém /var/lib/worker-integration (ledger) e /etc/worker-integration (config + segredo) — útil para reinstalar sem reconfigurar. O --purge apaga também esses diretórios.

12. Checklist de go-live

  1. Servidor pronto — Linux x86_64 com systemd, NTP sincronizado, wcertdox no ar em localhost.
  2. Firewall — saída HTTPS (443) liberada para a Cloud; nenhuma regra de entrada criada.
  3. Itens recebidos — pacote tar.gz, segredo HMAC (canal seguro) e URL da Cloud do ambiente.
  4. Config preenchida — worker.env sem CHANGE-ME; CLOUD_HMAC_PATH_PREFIX correto para o ambiente.
  5. Instalado — install-service.sh concluiu sem erro; usuário do serviço escolhido.
  6. No ar — systemctl is-active = active; /healthz ok; /readyz com tudo true; logs sem Falha AUTH.
  7. Primeiro evento validado — events_received, events_delivered e acks_sent subiram juntos; evento conferido no destino.
  8. Boot — systemctl enable confirmado (o serviço sobe sozinho após reinício do servidor).
